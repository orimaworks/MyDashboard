🌿 Git — Guide complet

Git est un système de gestion de versions distribué permettant de suivre les modifications, travailler en branches, collaborer et revenir facilement à un état antérieur d'un projet.


1️⃣ Initialisation et configuration

  • git --version : vérifier la version de Git.
  • git config --global user.name "Nom Prénom" : configurer son nom pour les commits.
  • git config --global user.email "email@exemple.com" : configurer son adresse e-mail pour les commits.
  • git config --list : afficher la configuration.
  • git init : créer un dépôt Git dans le répertoire courant.
  • git clone URL_DU_REPO : cloner un dépôt existant.

2️⃣ État et inspection

  • git status : consulter l'état du dépôt et les fichiers modifiés, indexés ou non suivis.
  • git diff : afficher les différences non indexées.
  • git diff --staged : afficher les différences indexées, prêtes à être incluses dans un commit.
  • git log --oneline --graph --decorate --all : consulter l'historique sous forme compacte avec les branches.
  • git show HASH : afficher les informations et les modifications d'un commit.
  • git blame fichier : identifier l'auteur associé aux modifications de chaque ligne.

💡 Réflexe : toujours consulter git status puis git diff avant un commit.


3️⃣ Ajouter des fichiers et créer des commits

  • git add fichier : indexer un fichier précis.
  • git add . : indexer les modifications présentes sous le répertoire courant.
  • git commit -m "Message clair et précis" : créer un commit avec un message explicite.
  • git commit --amend : modifier le dernier commit, notamment son contenu ou son message.
  • git commit --amend -m "Nouveau message" : modifier uniquement le message du dernier commit.

✔ Bon message : privilégier un message court, précis et représentatif des changements. Exemples : feat: ajouter la recherche, fix: corriger le tri, docs: compléter le guide.


4️⃣ Modifier ou supprimer des fichiers

  • git rm fichier : supprimer le fichier du répertoire de travail et indexer sa suppression.
  • git rm --cached fichier : retirer le fichier du suivi Git sans le supprimer du disque.
  • git mv ancien nouveau : renommer ou déplacer un fichier en indexant l'opération.
  • git restore fichier : restaurer le fichier depuis son état indexé, en abandonnant ses modifications non indexées.
  • git restore --source=HASH fichier : restaurer le fichier à partir d'un commit donné.

5️⃣ Gestion des branches

  • git branch : afficher les branches locales.
  • git branch feature-login : créer une branche sans basculer dessus.
  • git switch -c feature-login : créer une branche et basculer dessus.
  • git checkout -b feature-login : ancienne syntaxe pour créer une branche et basculer dessus.
  • git switch main : basculer vers la branche main.
  • git branch -d feature-login : supprimer une branche locale déjà fusionnée.
  • git push origin --delete feature-login : supprimer une branche distante.

📌 Règle : une branche = une fonctionnalité ou un correctif.


6️⃣ Fusion et réécriture de l'historique

  • git merge feature-login : fusionner la branche indiquée dans la branche courante.
  • git rebase main : replacer les commits de la branche courante au-dessus de main, pour obtenir un historique linéaire.
  • git rebase -i HEAD~3 : réorganiser interactivement les trois derniers commits pour les fusionner, les réordonner, modifier leurs messages ou en supprimer.

À retenir : le merge conserve la structure de l'historique ; le rebase réécrit les commits concernés. Évite de rebaser des commits déjà partagés sans coordination avec l'équipe.


7️⃣ Corriger une erreur avant le push

  • git restore --staged fichier : retirer un fichier de l'index sans annuler ses modifications locales.
  • git reset --soft HEAD~1 : supprimer le dernier commit tout en conservant les changements dans l'index.
  • git reset --hard HEAD~1 : revenir au commit précédent et abandonner les modifications suivies concernées.

Exemple : reprendre le dernier commit pour le corriger

git reset --soft HEAD~1
git add .
git commit -m "Commit corrigé"

Le dernier commit est retiré de la branche et ses changements restent disponibles pour créer un nouveau commit.

⚠️ Attention : git reset --hard peut supprimer des modifications locales non sauvegardées. Vérifie l'état du dépôt avant de l'utiliser.


8️⃣ Après un push : cas sensible

Réécrire l'historique ne doit être fait que sur une branche personnelle ou après accord de l'équipe.

  • git push --force : forcer la mise à jour distante, au risque d'écraser des commits présents sur le serveur.
  • git push --force-with-lease : forcer la mise à jour en vérifiant que la référence distante correspond à celle attendue localement.

🛡️ Recommandation : préférer --force-with-lease à --force. Cette option réduit les risques, mais ne rend pas l'opération sans danger.

🚫 Évite de forcer sur main en équipe.


9️⃣ Annuler un commit proprement

  • git revert HASH : créer un nouveau commit qui inverse les changements d'un commit existant.

Contrairement à reset, cette méthode conserve l'historique et convient aux branches partagées.


🔟 Gestion du dépôt distant

  • git remote -v : afficher les dépôts distants configurés.
  • git remote add origin URL : ajouter un dépôt distant nommé origin.
  • git remote set-url origin NOUVELLE_URL : modifier l'URL du dépôt distant.
  • git push -u origin main : publier main pour la première fois et définir sa branche de suivi.
  • git push : envoyer les commits vers le dépôt distant configuré.
  • git pull --rebase : récupérer les modifications distantes puis rejouer les commits locaux au-dessus de celles-ci.

✔ Bonne pratique : préférer git pull --rebase lorsque le workflow de l'équipe repose sur le rebase, afin d'éviter certains commits de merge inutiles.


1️⃣1️⃣ Stash — mettre son travail de côté

  • git stash : mettre temporairement de côté les modifications suivies du répertoire de travail et de l'index.
  • git stash list : afficher les stash enregistrés.
  • git stash pop : réappliquer le stash le plus récent et le retirer de la liste si l'application réussit.
  • git stash apply : réappliquer un stash sans le supprimer de la liste.

Pratique avant de changer rapidement de branche. Par défaut, les fichiers non suivis ne sont pas inclus.


1️⃣2️⃣ Nettoyage du dépôt

  • git clean -n : prévisualiser les fichiers non suivis qui seraient supprimés.
  • git clean -f : supprimer les fichiers non suivis.
  • git clean -fd : supprimer les fichiers et les dossiers non suivis.

⚠️ Prudence : toujours utiliser -n avant git clean pour vérifier ce qui sera supprimé.


1️⃣3️⃣ Commandes avancées

  • git reflog : consulter l'historique des déplacements des références locales et retrouver parfois des commits devenus difficiles d'accès.
  • git cherry-pick HASH : appliquer un commit précis sur la branche courante.
  • git bisect start : démarrer une recherche dichotomique pour identifier le commit qui a introduit un bug. La recherche nécessite ensuite de définir les états bon et mauvais, puis de tester les commits proposés.

🌐 Cloner un projet puis le rattacher à son GitHub

  1. Ouvrir l'IDE.
  2. Choisir Git → Clone.
  3. Saisir l'URL du dépôt source.
  4. Cloner le projet.
  5. Créer un nouveau dépôt vide sur GitHub.
  6. Ouvrir le terminal dans le projet.

Remplacer le dépôt distant

git remote -v
git remote set-url origin https://github.com/ORIMAWORKS/NOM_NOUVEAU_DEPOT.git
git push -u origin main

Cette opération conserve l'historique Git local tout en publiant le projet dans ton dépôt personnel. Vérifie que le dépôt distant cible est bien celui que tu souhaites utiliser.


🧠 Workflow recommandé

git switch main
git pull --rebase
git switch -c feature-ma-fonction

# Développement...
git status
git diff
git add .
git commit -m "feat: nouvelle fonctionnalité"

git switch main
git pull --rebase
git merge feature-ma-fonction
git push

✅ Bonnes pratiques

  • ✔ Faire des commits petits et atomiques.
  • ✔ Écrire des messages explicites : feat, fix, docs, refactor…
  • ✔ Créer une branche par fonctionnalité.
  • ✔ Éviter de travailler directement sur main.
  • ✔ Vérifier git status avant un commit.
  • ✔ Lire git diff avant de valider les modifications.
  • ✔ Utiliser un fichier .gitignore dès le début du projet.
  • ✔ Préférer git pull --rebase lorsque le workflow le permet.
  • ✔ Réserver --force aux situations maîtrisées.
  • ✔ Privilégier un historique compréhensible plutôt qu'un historique simplement rapide à produire.

📋 Mémo rapide

  • git status : état du dépôt.
  • git diff : consulter les modifications.
  • git add . : indexer les modifications sous le répertoire courant.
  • git commit -m "message" : créer un commit.
  • git switch -c nom : créer une branche et basculer dessus.
  • git merge nom : fusionner une branche dans la branche courante.
  • git rebase main : replacer les commits au-dessus de main.
  • git stash : mettre temporairement de côté les modifications suivies.
  • git revert HASH : annuler un commit en créant un commit inverse.
  • git reflog : rechercher un ancien état d'une référence locale.
  • git push : envoyer les commits vers le dépôt distant.
  • git pull --rebase : synchroniser le dépôt en rebasant les commits locaux.
