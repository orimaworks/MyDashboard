🌿 Git — Guide complet

Git est un système de gestion de versions distribué permettant de suivre les modifications, travailler en branches, collaborer et revenir facilement à un état antérieur d'un projet.

🎯 Objectif

  • Maîtriser les bases de Git
  • Gérer proprement les branches
  • Corriger les erreurs avant et après un push
  • Réécrire l'historique lorsque c'est pertinent
  • Adopter les bonnes pratiques d'un développeur expérimenté

1️⃣ Initialisation & configuration

Vérifier la version

git --version

Configurer son identité (globale)

git config --global user.name "Nom Prénom"
                 git config --global user.email "email@exemple.com"

Afficher la configuration

git config --list

Créer un dépôt Git

git init

Cloner un dépôt existant

git clone URL_DU_REPO

2️⃣ État & inspection

Voir l'état du dépôt

git status

Différences non indexées

git diff

Différences prêtes à être commit

git diff --staged

Historique lisible

git log --oneline --graph --decorate --all

Afficher un commit

git show HASH

Identifier l'auteur d'une ligne

git blame fichier

💡 Réflexe : toujours consulter status puis diff avant un commit.

3️⃣ Ajouter & commit

Ajouter un fichier

git add fichier

Ajouter toutes les modifications

git add .

Créer un commit

git commit -m "Message clair et précis"

Modifier le dernier commit

git commit --amend

Modifier uniquement son message

git commit --amend -m "Nouveau message"

✔ Bon message :

4️⃣ Modifier ou supprimer des fichiers

Action Commande
Supprimer du dépôt git rm fichier
Retirer du suivi uniquement git rm --cached fichier
Renommer git mv ancien nouveau
Annuler les modifications git restore fichier
Restaurer depuis un commit git restore --source=HASH fichier

5️⃣ Gestion des branches

Voir les branches

git branch

Créer une branche

git branch feature-login

Créer + basculer

git switch -c feature-login

Ancienne syntaxe :

git checkout -b feature-login

Changer de branche

git switch main

Supprimer une branche locale

git branch -d feature-login

Supprimer une branche distante

git push origin --delete feature-login

📌 Règle : une branche = une fonctionnalité ou un correctif.

6️⃣ Merge & Rebase

Fusion classique

git merge feature-login

Conserve l'historique tel quel.

Rebase

git rebase main

Replace les commits de la branche au-dessus de main pour obtenir un historique linéaire.

Rebase interactif

git rebase -i HEAD~3

Permet de :

  • squash plusieurs commits
  • réorganiser l'ordre
  • modifier un message
  • supprimer un commit

7️⃣ Corriger une erreur avant le push

Retirer un fichier ajouté par erreur

git restore --staged fichier

Le fichier reste modifié localement mais ne fera plus partie du prochain commit.

Corriger le dernier commit

   git reset --soft HEAD~1
                    git add .
                    git commit -m "Commit corrigé"

Le commit disparaît, mais toutes les modifications sont conservées.

Annuler complètement le dernier commit

Conserver les fichiers :

git reset --soft HEAD~1

Supprimer également les modifications :

git reset --hard HEAD~1

⚠️ Attention : --hard détruit définitivement les modifications non sauvegardées.

8️⃣ Après un push (cas sensible)

Réécrire l'historique ne doit être fait que sur une branche personnelle ou après accord de l'équipe.

Force push

git push --force

Version recommandée

git push --force-with-lease
  • Vérifie que personne n'a poussé entre-temps
  • Beaucoup plus sûre que --force

🚫 Ne jamais forcer sur main en équipe.

9️⃣ Annuler un commit proprement

Créer un nouveau commit qui inverse les modifications :

git revert HASH

Contrairement à reset, cette méthode conserve l'historique et est adaptée aux branches partagées.

🔟 Gestion du dépôt distant

Voir les remotes

git remote -v

Ajouter un remote

git remote add origin URL

Modifier son URL

git remote set-url origin NOUVELLE_URL

Premier push

git push -u origin main

Push suivant

git push

Récupérer les modifications

git pull --rebase

✔ Préférer toujours pull --rebase afin d'éviter les commits de merge inutiles.

1️⃣1️⃣ Stash

Mettre son travail temporairement de côté.

Sauvegarder

git stash

Lister

git stash list

Récupérer et supprimer

git stash pop

Appliquer sans supprimer

git stash apply

Idéal avant de changer de branche rapidement.

1️⃣2️⃣ Nettoyage

Prévisualiser

git clean -n

Supprimer les fichiers non suivis

git clean -f

Inclure les dossiers

git clean -fd

⚠️ Toujours utiliser -n avant un clean.

1️⃣3️⃣ Niveau avancé

Reflog — Sauvetage ultime

git reflog

Permet de retrouver des commits perdus, même après un reset.

Cherry-pick

git cherry-pick HASH

Copie un commit précis dans une autre branche.

Bisect

git bisect start

Recherche automatiquement le commit ayant introduit un bug grâce à une recherche dichotomique.

🌐 Cloner un projet puis le rattacher à son GitHub

Étapes

  1. Ouvrir l'IDE
  2. Onglet Git → Clone
  3. Saisir l'URL du dépôt source
  4. Cloner le projet
  5. Créer un nouveau dépôt vide sur GitHub
  6. Ouvrir le terminal dans le projet

Remplacer le dépôt distant

git remote -v
            git remote set-url origin \
            https://github.com/DEVMJ00/NOM_NOUVEAU_DEPOT.git

            git push -u origin main

Cette opération conserve l'historique Git tout en publiant le projet dans ton dépôt personnel.

🧠 Workflow recommandé

git switch main
            git pull --rebase
            git switch -c feature-ma-fonction

            # Développement...
            git status
            git diff
            git add .
            git commit -m "feat: nouvelle fonctionnalité"

            git switch main
            git pull --rebase
            git merge feature-ma-fonction
            git push

✅ Bonnes pratiques

  • ✔ Commits petits et atomiques
  • ✔ Messages explicites (feat, fix, docs, refactor...)
  • ✔ Une branche par fonctionnalité
  • ✔ Éviter de travailler directement sur main
  • ✔ Toujours vérifier git status avant un commit
  • ✔ Lire git diff avant de valider les modifications
  • ✔ Utiliser un .gitignore dès le début du projet
  • ✔ Préférer git pull --rebase à git pull
  • ✔ Réserver --force aux branches personnelles
  • ✔ Un historique propre vaut mieux qu'un historique rapide

📋 Mémo rapide

            git status              État du dépôt
            git diff                Modifications
            git add .               Indexer
            git commit -m           Commit
            git switch -c           Nouvelle branche
            git merge               Fusion
            git rebase              Historique linéaire
            git stash               Mettre de côté
            git revert              Annuler proprement
            git reflog              Sauver un historique perdu
            git push                Envoyer
            git pull --rebase       Synchroniser
