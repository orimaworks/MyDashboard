JSON

JavaScript Object Notation est un format léger d'échange de données, indépendant du langage de programmation utilisé. Il est facile à lire et à écrire pour les humains, et simple à analyser pour les machines.

JSON est couramment utilisé pour les fichiers de configuration, les échanges entre applications et les réponses des API.


📝 Structure de base

JSON repose sur deux structures principales :

  • Objet : une collection de paires clé/valeur, délimitée par des accolades {}.
  • Tableau : une liste ordonnée de valeurs, délimitée par des crochets [].

Exemple d'objet :

{
  "nom": "Orima",
  "version": 2.0
}

Exemple de tableau :

[
  "HTML",
  "CSS",
  "JavaScript"
]

Les objets et les tableaux peuvent être imbriqués les uns dans les autres pour représenter des données complexes. 

{
  "utilisateur": {
    "nom": "Alex",
    "actif": true
  },
  "roles": ["admin", "éditeur"]
}

🔤 Types de données

JSON accepte six catégories de valeurs :

  • string — chaîne de caractères entre guillemets doubles.
  • number — nombre entier ou décimal, sans guillemets.
  • object — objet contenant des paires clé/valeur.
  • array — tableau de valeurs ordonnées.
  • boolean — valeur logique true ou false.
  • null — absence de valeur.

Exemple regroupant ces types :

{
  "texte": "chaîne",
  "nombre": 42,
  "decimal": 3.14,
  "actif": true,
  "vide": null,
  "liste": [1, 2, 3],
  "objet": {
    "cle": "valeur"
  }
}

Attention : undefined, les fonctions, les commentaires et les valeurs comme NaN ne font pas partie de la syntaxe JSON.


⚙️ Syntaxe et règles

  • Les clés des objets doivent être des chaînes entre guillemets doubles.
  • Les chaînes utilisent des guillemets doubles, jamais des apostrophes seules.
  • Les éléments d'un objet et d'un tableau sont séparés par des virgules.
  • Aucune virgule ne doit suivre le dernier élément.
  • Les commentaires ne sont pas autorisés.
  • Les valeurs booléennes et null s'écrivent en minuscules.
  • Le séparateur décimal est le point, jamais la virgule.

Exemple invalide :

{
  "nom": "test",
  // Commentaire interdit
  valeur: "error",
}

Version valide :

{
  "nom": "test",
  "valeur": "error"
}

JSON est un format de données, et non du code JavaScript : un objet JavaScript peut notamment contenir des commentaires, des propriétés sans guillemets et des fonctions, contrairement à JSON.


🔄 JSON et JavaScript

JavaScript fournit deux méthodes essentielles pour convertir des données entre le format JSON et les objets manipulés dans le code.

JSON.parse() — transforme une chaîne JSON en valeur JavaScript.

const json = '{"nom":"Orima","actif":true}';

const donnees = JSON.parse(json);

console.log(donnees.nom); // "Orima"

JSON.stringify() — convertit une valeur JavaScript en chaîne JSON.

const utilisateur = {
  nom: "Orima",
  actif: true
};

const json = JSON.stringify(utilisateur);

console.log(json);
// {"nom":"Orima","actif":true}

JSON.parse() peut lever une erreur si la chaîne n'est pas un JSON valide. En pratique, il est donc préférable de gérer cette éventualité avec try...catch lorsque les données ne sont pas maîtrisées. 

try {
  const donnees = JSON.parse(texteJson);
  console.log(donnees);

} catch (erreur) {
  console.error("JSON invalide :", erreur.message);

}

🛠️ Validation et formatage

Quelques outils utiles pour contrôler un fichier JSON :

  • JSONLint — validation de la syntaxe.
  • JSON Formatter — validation et mise en forme.
  • jq — outil en ligne de commande pour lire, filtrer et transformer du JSON.

Exemples avec jq :

# Afficher le JSON avec indentation
jq '.' fichier.json

# Extraire la valeur de la clé "nom"
jq '.nom' fichier.json

# Afficher les éléments du tableau "roles"
jq '.roles[]' fichier.json

Dans VS Code, un fichier JSON peut être formaté avec Shift + Alt + F sous Windows. Le raccourci peut varier selon les raccourcis configurés.


📐 JSON Schema

JSON Schema permet de décrire la structure attendue d'un document JSON : propriétés obligatoires, types, valeurs autorisées et contraintes. Il est utile pour valider les données échangées entre applications.

Exemple de schéma simple :

{
  "type": "object",
  "properties": {
    "nom": {
      "type": "string"
    },
    "version": {
      "type": "number"
    }
  },
  "required": ["nom", "version"],
  "additionalProperties": false
}

Ce schéma exige un objet contenant les propriétés nom et version, respectivement de type chaîne et nombre. Il interdit également les propriétés supplémentaires.


💾 Bonnes pratiques

  • Utiliser l'encodage UTF-8.
  • Indenter les données pour faciliter leur lecture et leur maintenance.
  • Choisir des noms de clés explicites et cohérents.
  • Valider les données reçues d'une API ou d'un utilisateur.
  • Utiliser JSON Schema lorsque la structure doit respecter un contrat précis.
  • Éviter de stocker des mots de passe, jetons d'accès ou autres secrets en clair.
  • Ne minifier le JSON que lorsque cela présente un intérêt, par exemple pour réduire la taille d'un fichier transmis.
